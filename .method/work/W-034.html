Résultat attendu
Les cas multijoueurs que la recette UAT-002 n'a pas pu valider sont couverts par des tests automatiques, et tout défaut révélé est corrigé : départ de l'hôte, arrivée en cours de match, reconnexion tardive, deux humains dans la même équipe, abandon d'un manager.
Pourquoi (PO)
Le jeu à deux amis via un code de salon est un critère de réussite de la vision ; ces cas sont fréquents dans la vraie vie et non prouvés aujourd'hui.
Périmètre et points d'entrée

Vérification prévue
npm test ; un test par scénario (cinq critères) ; si un test échoue sur le code actuel, consigner d'abord un constat AC-005… (origine, reproduction) puis corriger dans ce lot.
Points d'attention
Ne pas affaiblir les validations serveur (le serveur fait autorité). Les tests doivent rester déterministes (pas de dépendance au temps réel au-delà des délais déjà utilisés dans les tests existants).

Critères d'acceptation

Salon d'attente (Arène et Manager) : l'hôte part → un autre humain devient hôte et peut lancer la partie.

« départ de l'hôte au salon » : après leave de l'hôte, le membre suivant devient hôte (hostId + you.host) et lance — Arène : phase « playing » ; Manager : phase « draft » avec bot sur le siège libéré. Défaut réel trouvé et consigné (AC-005) : startDraft exigeait un occupant « home » — corrigé, tout siège sans humain est pris par un manager virtuel.

Arène : un humain qui rejoint en cours de match remplace un bot de l'équipe la moins pourvue et reçoit l'état initial puis les instantanés.

« arrivée en cours de match » : un humain qui rejoint une Arène en jeu est placé dans l'équipe sans humain (b parti), le joueur passe sous contrôle humain (sim.players[seat].human), a.init reçu puis les a.snap suivent l'init.

Reconnexion tardive (≥ 30 s après la coupure) au même match → le joueur retrouve sa place (même identité), sans dupliquer de joueur.

« reconnexion tardive (≥ 30 s) » sur serveur réel : socket coupé, bot en relève (left + human=false), 31 s réelles d'attente, reconnexion avec le même guestId → room.joined avec la même place, a.init renvoyé, left=false, exactement 2 humains (aucun doublon). Durée 31 077 ms.

Arène à deux humains dans la même équipe : le changement de joueur (manuel ou automatique) ne prend jamais le joueur de l'autre humain.

« deux humains dans la même équipe » : a.switch vers la place de l'autre humain refusé dans les deux sens ; a.switch « auto » choisit toujours un coéquipier bot — bestSwitchTarget exclut les joueurs humains et switchTo refuse toute place occupée.

Manager : un manager qui quitte en plein match est remplacé par le bot ; son résultat est enregistré comme abandon, sans erreur serveur ; npm test vert.

« abandon en plein match » : leave en phase « playing » → BotManager en relève (bots.away), place marquée left ; fin de match → onResults reçoit l'entrée du partant avec abandoned=true (abandoned=false pour le joueur resté), rapport diffusé sans erreur. npm test : 148/148.

Définition de fini commune : feuille de route, section « Définition de fini ». Statut cible après livraison : review avec preuves (l'acceptation reste à Guillaume).
