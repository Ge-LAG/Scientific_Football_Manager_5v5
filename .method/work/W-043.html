Jeu hors ligne installable (PWA)

Sprint
Sprint 10 (M9) — Accessible partout
Résultat attendu
Après une première visite en ligne, le site se recharge sans réseau et le solo (Arène et Manager contre les bots) fonctionne ; le jeu s'installe comme une application (manifeste, icônes) ; les fonctions en ligne affichent clairement « hors ligne » ; une nouvelle version déployée propose « Recharger ».
Pourquoi (PO)
Le hub du Manager annonce « Fonctionne même hors ligne » : à vérifier d'abord (sans service worker, un rechargement hors ligne échoue probablement), puis rendre l'affirmation vraie.
Périmètre et points d'entrée
Nouveaux public/manifest.webmanifest, icônes dans public/, service worker (liste des fichiers construits générée au build, par exemple par un petit plugin Vite ou un script après vite build) ; enregistrement en production seulement dans src/main.jsx ; lien du manifeste dans index.html ; état hors ligne dans src/net/connection.js, src/game/GameProvider.jsx.
Hors périmètre
Notifications push, synchronisation en arrière-plan.
Dépendances
W-032 (scripts navigateur).
Vérification prévue
Étape 1 : vérifier et consigner (constat AC) le comportement actuel hors ligne. Puis smoke : chargement en ligne, réseau coupé (Network.emulateNetworkConditions du protocole DevTools), rechargement → accueil, Arène solo et Manager contre bot lancés ; fonctions en ligne → message hors ligne sans exception.
Points d'attention
Ne jamais mettre en cache /api/ ni le WebSocket ; versionner le cache et nettoyer les anciennes versions ; le serveur de développement Vite ne doit pas être affecté.

Critères d'acceptation

Comportement hors ligne actuel vérifié et consigné avant toute modification.

Après une visite, rechargement sans réseau → accueil, Arène solo et Manager contre bot jouables (smoke).

Fonctions en ligne : message « hors ligne » clair, aucune exception.

Manifeste valide (nom, icônes 192 et 512, start_url, display: standalone) ; bandeau « Nouvelle version — recharger ».

/api/ et WebSocket jamais en cache ; textes FR/EN ; npm test et build verts.

Définition de fini commune : feuille de route, section « Définition de fini ». Statut cible après livraison : review avec preuves (l'acceptation reste à Guillaume).
