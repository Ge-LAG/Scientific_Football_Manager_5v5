Changement de joueur en cours de match

Résultat attendu
Quand l'équipe n'est pas entièrement humaine, le joueur change de scientifique contrôlé en cours de match (touche, bouton manette, clic sur le bandeau d'équipe) ; le serveur valide ; le joueur quitté redevient un bot ; option de changement automatique (suivre ses passes, aide défensive).
Périmètre / mandat
shared/action, shared/rooms, src/three, src/pages/arena. Mandat : demandes d'amélioration du PO (2e message du 2026-09-27) et arbitrages validés par le PO (apparence visible de tous, 2 power-ups choisis avant le match, ressources CC0 autorisées, commit sur la branche lab-league-v3).
Dépendances
W-012.
Vérification prévue
npm test (tests/loadout-switch.test.js) + parcours navigateur.
Point d'étape
Livré : message a.switch (cible « auto » = meilleur coéquipier, ou place précise), validation serveur (même équipe, jamais un humain, places des coéquipiers déconnectés réservées, délai 250 ms), pilote seul changé (setControl), entrées reportées, actions créditées au pilote humain du moment (tirs, tacles, arrêts, buts, passes décisives), bandeau d'équipe cliquable, touche / LB, suivi automatique après passe et aide défensive (option). Relecture : AC-002.

Critères d'acceptation

Changement vers un coéquipier bot accepté, vers un humain ou un adversaire refusé ; l'état de jeu est conservé (test).

Les statistiques personnelles cumulent les joueurs contrôlés (test) ; la vue suit le nouveau joueur sans rechargement.

Changement vers un bot accepté ; vers un humain, un adversaire, une place réservée, une clé hostile ou un nombre décimal refusé ; l'autre humain garde son joueur ; état de jeu conservé.

Actions créditées au pilote du moment (but d'un tir de bot non attribué, pas d'homme du match « volé ») ; dans le navigateur la vue suit le nouveau joueur sans rechargement (capture 16b-arene-switch).
