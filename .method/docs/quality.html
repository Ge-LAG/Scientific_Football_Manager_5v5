Verification proportional to risk

ChangeEvidence before technical acceptance
Low impact: wording, docs, formattingReview the surface, links/rendering or existing formatter. No new test merely restating the edit.
Normal: behavior, bug fix, refactorRelevant automated tests and stack checks; affected contracts/critical paths. Add meaningful behavioral regression protection.
High: auth, sensitive data, schema, payment, public contract, concurrency or wide refactorNegative cases and integration/contract checks; trust-boundary and failure-recovery review. Record recovery and obtain a distinct technical review when required by risk/mandate.
Release candidateConfigured release checks on the candidate revision/artifact, deployment acceptance and operational evidence.

Prefer a reproducing failing test followed by a passing test for bugs when practical. If hardware/services prevent reproduction, record the limitation and closest meaningful validation. Unavailable required checks do not become passes. Reuse useful tests; avoid tests coupled to implementation details.

Build order follows stack dependencies: compilation may precede tests. Diagnostic builds are allowed. Failures block acceptance/promotion of the affected candidate, not investigation. Full regression belongs at meaningful integration/release boundaries and wherever changed risk requires it.

Project CI commands are the executable check definition. Specify working directory and exact commands in the profile; fail on required command errors. Do not silently skip missing commands. A known unrelated/flaky failure needs an issue, impact assessment, owner and time-bounded exception approved by the responsible owner before acceptance. Rerunning until green is not a fix.

Evidence: criterion, exact command or manual steps, date, code/artifact revision or identified dirty diff, environment, result, log/artifact location and limitation. Keep large logs outside hot context; return a concise outcome or failing excerpt with a pointer. Invalidate checks affected by changed code, dependencies or environment.

Apply localization checks for user-facing changes. A second agent is optional only when authorized and likely to find distinct defects; give it bounded scope and evidence. Model agreement alone is not validation.

Use the structured closure contract for passing results and expiring exceptions. Required checks remain proportional to risk.
