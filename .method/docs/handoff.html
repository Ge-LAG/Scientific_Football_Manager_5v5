CTO ↔ Codex handoff

Robertson sends an English task through the available Codex interface. Confirm the visible project and task before sending; observe receipt in that task afterward. Do not assume hidden application state, shared filesystem access, automatic wakeups or a working integration.

WORK: W-042 / revision 3 / target project and Codex task
Outcome: one observable result.
Acceptance: A1 …; A2 …
Scope: affected components; exclusions when needed.
Mandate: permitted actions and relevant boundaries.
Context: current code ref + profile/decision/work IDs.
Next action: implement, review, investigate or collect feedback.

Replace fields already in the work record with its ID, revision and accessible link. If a reference is inaccessible, send only the relevant excerpt and origin. Codex retrieves implementation details itself. Acknowledgement can be part of the normal progress update, not another approval round.

Before retrying delivery, inspect the target task for the work ID and revision. If already received/running, continue the same task; do not duplicate work. A changed instruction identifies the delta. Repeated delivery of the same revision does not repeat side effects.

WORK: W-042 / revision 3
State: review | blocked | accepted
Result: observed behavior and change scope.
Evidence: code/artifact ref; checks + outcome; evidence links.
Open: unresolved risk or one decision, if any.
Next: exact action and responsible actor.

This return to Robertson is English. Intermediate/final reports for Guillaume are French. If both need a report, produce a short French PO summary and an English CTO delta, without translating all technical history twice. Software strings follow the bilingual contract.

Robertson verifies criteria against artifacts/evidence, requests corrections in the same record and consults Guillaume for reserved product decisions. A screenshot proves only what it shows; task completion is not deployment evidence.

Use status/completion events when available; otherwise inspect the visible task at useful milestones. Avoid repeated unchanged screenshots and polling. A disconnected computer-use session is a delivery limitation, not a reason to invent progress.
