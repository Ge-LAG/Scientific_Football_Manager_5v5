Release and operate

  1. Identify. Record code revision, lockfiles, artifact identity/digest and target environment. Build reproducibly through the actual pipeline; test the packaged artifact where applicable.
  2. Verify. Complete required regression/integration, critical-path smoke, security and bilingual UI checks. Verify accessibility, performance and resource limits against explicit targets where required.
  3. Prepare operations. Configuration/secret references, migration order, backup/recovery, rollout, health signals, alert owner and stop/recovery criteria. Record effects and authority.
  4. Promote within mandate. Implementation/preparation permission does not imply deployment permission. Finish a reviewable candidate; request only missing authority. Version/tag identifies that candidate.
  5. Observe. Verify deployed revision/health, affected critical paths and migrations. Record measured outcomes. Escalate/recover at stop criteria; artifact preparation is not deployment.

Use a release record. Accepted means the candidate satisfies gates; released requires observed promotion to its target. Product and technical approvals remain separate when both are required.

The V6 tool validates method records, not software quality. Add python .method/tools/method.py validate --project-ready to existing CI alongside actual stack checks. Required promotion gates fail on errors; compile/test order follows dependencies. Configure real commands in profile. No universal script supplies a project's deployment policy.

For incidents, preserve evidence and stabilize within mandate, then assess impact, recover and check health. Record cause, correction and useful regression protection in incident; prevention goes to owned backlog work.
