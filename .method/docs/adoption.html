Adopt V6 in a project

  1. Copy this folder to the target repository as .method/. Retain V5/project evidence until reconciliation.
  2. For an existing project, follow migration. Fill profile with observed architecture, constraints and check commands; map the roadmap. Replace their draft status when configured.
  3. Create a work file from the HTML template, with unique ID, real criteria and ready/active status. Configure project.json: name, mode, focus_id, next_action, date/revision. Set template=false only after configuration.
  4. Run python .method/tools/method.py reindex and python .method/tools/method.py validate --project-ready. This checks adoption fields; review actual content and run real software checks separately.
  5. Use the launch text below. Verify a fresh task loads only expected context, without old V5 instructions through another entry point.

Runtime: Python 3.10+ is required for CLI commands. If Windows python points to an unavailable Store alias, use a working Python executable or the runtime located by Codex workspace dependencies. A browser remains sufficient for manual reading. Without the CLI, follow explicit data-requires and select applicable constraints from the index manually; automated integrity/closure checks remain unavailable until the runtime is restored.

HTML-only automatic entry point

Copy START.html to the repository root as START.html; prefix its local links/stylesheet with .method/. Add START.html to the existing project_doc_fallback_filenames array in Codex configuration, preserving existing entries/settings:

project_doc_fallback_filenames = ["START.html"]

Start a fresh run and verify START.html loaded. Codex checks AGENTS.override.md and AGENTS.md before fallbacks; existing files in the same directory take precedence. Adding HTML alone does not activate it. The fallback mechanism is documented in official Codex documentation; verify behavior in the installed client.

If the project already uses AGENTS.md, add only the launch pointer there, retaining unrelated rules. V6 contains no Markdown documentation and requires no Markdown mirror. Do not rename real SKILL.md/platform-recognized files blindly; migrate applicable rules and retire conflicting activation separately.

This kit changes no global configuration or target software repository. Open index.html locally to browse; content is static and usable without JavaScript. The search box filters metadata; the CLI provides bounded retrieval.

Upgrade from V6.0

V6.1 keeps canonical HTML/project state and adds owner/revision metadata, dependency/review fields and structured closure evidence. Preserve closed history; archive it explicitly if it is historical evidence only. Do not fabricate missing proof for old accepted tasks. Reopen unresolved work for review. Discard generated indexes/cache, run reindex and full validate, then address health exceptions. Keep the bilingual policy and existing product acceptance unchanged.

New source schema fields are described in durability and evidence. Generated index schema is now 2. Reindex is required after copying/extracting the kit because file stamps belong to the local checkout.
