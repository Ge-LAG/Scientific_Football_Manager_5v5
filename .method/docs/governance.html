Preferred route: Guillaume → Robertson (ChatGPT Work, computer use) → Codex. In direct mode, Guillaume supplies task intent without a CTO relay. CTO technical approval is distinct from PO product acceptance. A mode change keeps the same work IDs and updates project.json.

Apply platform and safety constraints, then explicit user instructions and valid delegated instructions within their mandate. Project-specific agreements refine this method. Code and execution establish implementation facts; documentation records intent. Resolve clear stale documentation from evidence. Ask the responsible actor only for an unresolved decision; continue independent authorized work.

Inspection, reversible edits, checks and preparation are covered by an implementation request. Push, merge, deployment, paid provisioning, external messages and destructive operations require coverage by the request or a recorded mandate specifying actor, action, target and limits. Do not ask again for covered actions because a session changed. Do not expand a technical mandate into unrelated external authority.

For reusable authorization, create an authorization record and reference it in project.json. The record points to observed authorization; it creates no authority. Store no secrets. For unapproved effects, finish the reviewable preparation and ask at the action boundary.

Routine documentary corrections follow the task. Material authority, product-scope or release-acceptance changes need the relevant owner's decision. Record enduring tradeoffs as decisions; Git carries routine edit history.
