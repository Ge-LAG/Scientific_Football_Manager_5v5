guide / durability

Keep the method healthy

At a milestone, handoff across teams, architecture change or release, run health. Review its exceptions only. validate --project-ready is the full CI gate: it hashes/reparses all records and checks references, closure structure and stale evidence. These checks supplement software CI; they cannot prove the truth of a human-entered result.

Active rules have an owner

All active records declare data-owner and a positive data-revision. Active constraints and decisions additionally declare data-reviewed, data-review-by, data-review-trigger and data-review-digest. Review dates use YYYY-MM-DD. Choose a useful interval for the project's risk; the interval is not a new recurring approval ceremony.

A change in watched source, rule text or required reference invalidates the applicability fingerprint. An overdue date also requires owner review. Re-evaluate, then record the new fingerprint/date; never renew these mechanically. Event triggers that are not represented by watched files remain the owner's responsibility.

Dependencies are explicit

Use data-requires="ID ID" for mandatory references. Constraints use data-applies-to="component component" or data-paths="src/auth/*|api/auth/*"; * in data-applies-to means all tasks. Work declares data-components and/or data-watch. Pass actual changed filenames through context --paths as scope evolves. Explicit scope does not replace inspecting the real diff for omitted components.

Context includes matching constraints and the transitive data-requires closure, once per ID. Ordinary hyperlinks stay optional. Missing references, ambiguous successors and dependency/replacement cycles are rejected. If the complete context exceeds the output budget, use context --manifest and read every listed reference in batches; no mandatory rule is silently removed.

Replace decisions without erasing them

A reviewed successor declares data-supersedes="OLD-ID" and reaches accepted (or active for a constraint). New context resolves references to that successor; the previous decision remains readable as historical evidence. Only one current successor may claim the same predecessor. Reconcile incoming links and archive closed history by setting data-status=archived through a guarded replacement.

Archived files retain their path and ID, preserving links. Their metadata moves into archive-index.json; active metadata stays in index.json. History has its own paginated HTML view and explicit search --archive. Never rewrite archived records to match current reality; make a successor/correction. Old evidence describes its recorded candidate, not today's code.

Bounded growth

Health reports oversized core/profile/state/records and excessive active records using LIMITS in tools/durability.py. Defaults: core 2,300, profile/state 2,400, record 8,000 characters; 200 active records. These are review alerts, not automatic deletion or truncated obligations. A justified longer task can raise its output budget. Split optional detail and archive closed work before enlarging the always-loaded contract.

The regular context output remains capped at 12,000 characters. The browser shows 100 records per page; CLI search reports the total and supports --offset. Full reviews use health --limit/--offset. The tools do not impose additional model calls, automatic agents or recurrent notifications.

Fast path and integrity boundary

Reindex reuses an untracked local parse cache when file size and nanosecond modification time match. Search/context compare the inventory and these stamps; selected reads also check SHA-256. No archived body is loaded into ordinary model context. File enumeration and metadata still scale with corpus size; there is no constant-time claim.

Full validate and health bypass the cache. If a selected hash or full check finds a timestamp-preserving edit, run reindex --full to discard cached metadata and rebuild. Timestamp-preserving edits may evade the fast inventory check until a selected read/full validation; run full validation in CI and before release. Treat the cache as disposable. Do not use the fast path as a tamper-proof audit. Stale rules or evidence block the selected dependent context; unrelated items appear as maintenance warnings. Include every release-critical record in the current work’s data-requires so CI checks its applicability.
