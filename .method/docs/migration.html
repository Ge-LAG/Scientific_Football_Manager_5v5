V5 → V6 decisions

The supplied V5 is a generic template, not an initialized software project. Real PROJET state, product acceptance and application checks cannot be migrated from absent files. V5 and earlier archives remain historical sources; V6 is standalone.

Existing-project migration

  1. Inventory active constraints, decisions, work, audit findings, manual acceptance and authority. Preserve IDs, origin and evidence. Do not copy generic prose for file parity.
  2. Map active facts to profile, roadmap or one HTML record; keep current pointers in project.json. Preserve source links until reconciled.
  3. Resolve JSON/Markdown disagreement against code, evidence and owner intent. Mark unresolved facts explicitly.
  4. Validate references/state; rehearse a fresh task and CTO handoff. Compare missed constraints, acceptance quality and context volume.
  5. Archive superseded entry points and retire auto-loaded old instructions after accounting for active facts. Do not rewrite historical evidence solely to change format.

Redundant instruction overhead is removed; judgment and verification remain. Model capability cannot establish that a project's security, correctness or deployment requirements are already satisfied.
